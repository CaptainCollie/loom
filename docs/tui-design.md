# Интерактивный режим loom

Статус: проект описания. Основное управление и раскрывающееся дерево заданы пользователем. Детали, перечисленные в разделе «Предлагаемые решения», требуют согласования перед реализацией.

## Назначение и запуск

TUI позволяет создавать файлы, каталоги и целые структуры в терминале, видеть результат в дереве и просматривать содержимое файлов.

- `loom` запускает интерактивный режим в текущем рабочем каталоге.
- `loom "dir/{file1.rs, file2.rs}"` сохраняет существующее поведение CLI.
- Паттерны в TUI используют тот же синтаксис и проверки, что и CLI.

## Дерево и навигация

На экране отображается раскрывающееся дерево текущего рабочего каталога. Переход внутрь каталога не заменяет дерево отдельным списком: пользователь раскрывает и сворачивает ветки.

Экран содержит корневой путь, дерево с выделенным элементом, строку состояния и подсказки клавиш. При длинном дереве выделение остаётся в видимой области.

| Клавиша | Действие |
| --- | --- |
| `↑` / `↓` | Выбрать предыдущий / следующий видимый элемент |
| `→` | Раскрыть выбранный каталог; если он раскрыт — выбрать первого ребёнка |
| `←` | Свернуть выбранный раскрытый каталог; иначе выбрать родителя |
| `d` | Открыть ввод имени нового каталога |
| `f` | Открыть ввод имени нового файла |
| `s` | Открыть ввод паттерна структуры |
| `Backspace` | Открыть подтверждение удаления выбранного элемента |
| `Enter` | Открыть файл для чтения; на каталоге — раскрыть или свернуть его |
| `Esc` | Закрыть просмотр или отменить текущий диалог |
| `q` | Выйти из режима навигации |
| `Ctrl+C` | Выйти из TUI из любого режима |

Для пустого дерева корневой каталог остаётся доступен для выбора. На границах списка стрелки не переносят выделение на противоположный конец.

## Будущее оформление дерева: иконки и Git-статусы

Правила этого раздела согласованы для будущей реализации; они не означают, что поддержка Git уже добавлена.

### Независимое оформление частей строки

Каждая строка состоит из линий дерева, иконки, имени и отдельной колонки Git-статуса:

- Линии `│`, `├──`, `└──` имеют нейтральный цвет.
- Иконка и только её цвет определяются типом элемента, специальным именем или расширением файла. Для неизвестных типов используются стандартные иконки файла и каталога.
- Для специальных имён приоритет выше, чем для расширений: например, `Cargo.toml` может иметь собственную иконку независимо от остальных `.toml`.
- Цвет имени отражает состояние Git и не зависит от цвета иконки.
- Отметки Git-статуса выравниваются отдельной колонкой справа. Цвет дополняется символом, чтобы состояние можно было различить без восприятия цвета.
- Для отображения иконок Nerd Fonts пользователь должен выбрать соответствующий шрифт в настройках терминала.

### Цвета имён и отметки

| Состояние | Цвет имени | Отметка справа |
| --- | --- | --- |
| Новый неотслеживаемый файл | Зелёный | Зелёный `?` |
| Новый файл, добавленный в индекс | Зелёный | Голубой `✓` |
| Существующий файл с изменениями вне индекса | Жёлтый | Жёлтый `M` |
| Существующий файл с изменениями только в индексе | Жёлтый | Голубой `✓` |
| Изменения есть в индексе и после добавления в индекс | Зелёный для нового файла, жёлтый для существующего | Голубой `✓` и жёлтый `M` |
| Отслеживаемый файл без изменений | Нейтральный | Нет |
| Игнорируемый файл или каталог | Приглушённый | Нет |

Новый файл остаётся зелёным до первого коммита, в том числе если после добавления в индекс его снова отредактировали. Добавление в индекс меняет отметку подготовленности к коммиту, а не цвет имени. Неотслеживаемые файлы не приглушаются: приглушение предназначено для игнорируемых элементов.

Вне Git-репозитория имена отображаются нейтрально, без Git-отметок; иконки сохраняют оформление по типу элемента.

### Пример

В текстовом примере цвета не отображаются; соответствие задано таблицей выше.

```text
 loom/
├──  src/
│   ├──  main.rs       M
│   ├──  parser.rs     ✓
│   ├──  files.rs      ✓ M
│   ├──  icons.rs      ?
│   └──  theme.rs      ✓
├──  README.md
└──  target/
```

В этом примере `main.rs`, `parser.rs` и `files.rs` — изменённые существующие файлы с жёлтыми именами. `icons.rs` — новый неотслеживаемый файл, `theme.rs` — новый файл в индексе; оба имени зелёные. `README.md` не изменён и имеет нейтральное имя. `target/` игнорируется и отображается приглушённым. Иконки Rust-файлов имеют один выбранный для этого типа цвет независимо от Git-статуса имени.

### Отложенные решения

- Цвет каталогов по состояниям потомков требует отдельного определения приоритетов. До этого обычные имена каталогов нейтральные, игнорируемые — приглушённые.
- Отображение удалённых файлов красным отложено: отсутствующие элементы нужно получать из Git и отдельно определить допустимые действия и навигацию по ним.
- Конкретная палитра иконок и полный набор соответствий имён и расширений определяются при реализации. Состояния Git, не перечисленные в таблице, например конфликты и переименования, требуют отдельного проектирования.

## Создание и удаление

### Выбор каталога назначения

Если выделен каталог, новый элемент создаётся внутри него. Если выделен файл, новый элемент создаётся рядом с ним. Перед вводом интерфейс показывает полный путь каталога назначения; раскрытость ветки на выбор назначения не влияет.

### Создание через `d` и `f`

Открывается поле имени. `Enter` подтверждает создание, `Esc` отменяет его. В этих полях вводится одно имя; для вложенных структур предназначен режим `s`.

Пустое или недопустимое имя показывает ошибку и оставляет диалог открытым. Существующий объект не перезаписывается: интерфейс сообщает о совпадении имени. После успешного создания каталог назначения раскрывается, новый элемент становится выделенным.

### Создание через `s`

Пользователь вводит, например, `dir/{file1.rs, file2.rs, dir2/{file3.rs}}`. После `Enter` паттерн разбирается и целиком проверяется существующим механизмом, затем применяется относительно каталога назначения.

Существующие каталоги используются повторно, содержимое существующих файлов сохраняется, как в CLI. После выполнения дерево обновляется. Ошибка разбора или проверки оставляет поле ввода открытым для исправления.

Ошибки файловой системы во время применения могут оставить часть структуры созданной. Интерфейс сообщает об ошибке и обновляет дерево, чтобы показать фактический результат. Автоматического отката в первой версии нет.

### Удаление через `Backspace`

Сначала показывается подтверждение с полным путём. Для каталога явно указывается удаление вместе со всем содержимым. По умолчанию выбрана отмена; подтверждение требует отдельного выбора действия удаления.

После удаления выделяется соседний видимый элемент или родитель. Корень открытого дерева удалить нельзя. При ошибке интерфейс показывает причину и перечитывает содержимое затронутого каталога.

## Просмотр файлов

`Enter` на файле открывает режим чтения с отображением пути. `↑` / `↓` прокручивают текст, `PageUp` / `PageDown` прокручивают страницу. `Esc` возвращает в дерево, сохраняя выделение и раскрытые ветки.

Первая версия показывает текст UTF-8 без редактирования и подсветки синтаксиса. Для неподдерживаемого содержимого выводится понятное сообщение. Ошибка чтения не завершает TUI.

В просмотре и диалогах клавиши создания и удаления дерева не действуют. В поле ввода `d`, `f`, `s`, `q` являются обычными символами, а `Backspace` удаляет символ перед курсором.

## Предлагаемые решения для первой версии

Эти решения дополняют исходное описание пользователя:

- Корень фиксируется при запуске: навигация выше него не выполняется.
- При запуске раскрыт корень, вложенные каталоги свёрнуты. Каталоги читаются по мере раскрытия; всё поддерево заранее не сканируется.
- Каталоги показываются перед файлами, внутри групп — сортировка по имени. Скрытые элементы показываются, чтобы дерево отражало содержимое каталога.
- `r` в навигации обновляет дерево с сохранением доступного выделения и раскрытых веток. Постоянное наблюдение за файловой системой пока не требуется.
- Символические ссылки отображаются отдельным типом, но не раскрываются и не открываются. Удаление ссылки удаляет саму ссылку, без обхода её цели. Особенности Windows junction необходимо проверить при реализации.
- Просмотр читает не более 1 МиБ файла. Если файл больше, показывается доступный префикс с отметкой об ограничении. Некорректный UTF-8 внутри прочитанного содержимого даёт сообщение о неподдерживаемом формате; неполный последний символ из-за лимита отбрасывается.
- Удаление окончательное, без корзины и отмены. Это явно указывается в подтверждении.
- Без интерактивного терминала запуск без аргументов выдаёт понятную ошибку вместо запуска TUI.
- При выходе и при ошибках терминал восстанавливается: отключается raw mode и возвращается обычный экран.

## Подход к реализации

Выбранный вариант интерфейса — раскрывающееся дерево. Список содержимого одного каталога проще, но не соответствует выбранному пользователем поведению. Отдельная панель предварительного просмотра могла бы ускорить чтение, однако для первой версии достаточно отдельного режима просмотра по `Enter`.

Предлагается использовать Ratatui для отрисовки и Crossterm для событий терминала. Версии и совместимость с целевыми ОС проверяются при реализации. TUI вызывает существующий механизм разбора, проверки и применения паттернов; отдельный парсер не нужен.

Состояние интерфейса включает раскрытые каталоги, выбранный путь, прокрутку и текущий режим: навигация, ввод имени, ввод паттерна, подтверждение удаления или просмотр. Логика выбора и переходов отделяется от отрисовки, чтобы её можно было проверить без настоящего терминала.

## Проверка результата

- Запуск без аргументов открывает дерево текущего каталога, запуск с паттерном работает как раньше.
- Стрелки перемещают выделение только по видимым узлам; сворачивание скрывает потомков.
- Создание при выделенном файле и каталоге использует ожидаемое назначение; пустой каталог также позволяет создавать элементы.
- Недопустимое имя или паттерн не создают объектов до завершения предварительной проверки.
- Применение паттерна сохраняет содержимое существующих файлов.
- Отмена ввода и удаления ничего не меняет; удаление непустого каталога требует явного подтверждения.
- Просмотр поддерживает прокрутку, лимит размера и возврат к прежнему выделению; ошибки доступа и неподдерживаемые файлы не завершают приложение.
- Изменение размера окна и длинное дерево не теряют выделение; выход восстанавливает терминал.
- Основные сценарии проверяются на Windows, Linux и macOS. Совместимость не означает одинаковый набор допустимых имён файлов на всех ОС.

## За пределами первой версии

Редактирование содержимого, копирование и перемещение, переименование, поиск, вкладки, импорт JSON и tree, подсветка синтаксиса, корзина и отмена операций остаются отдельными будущими задачами.
